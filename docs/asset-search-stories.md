# Keepstack 素材检索：User Stories

验收依据：[题目 README](../README.md)，基线 `3aa137c`。本轮只修复现有页面的阻塞；新功能等 UI 确认后再开发。

## 1. 使用现有素材页面

- **故事：** 作为内容运营，我能登录 Library，打开详情并维护元数据和标签。
- **验收：** 通过登录表单查看素材；从详情保存标题和描述、添加并删除标签。现有集合入口能显示集合内的素材，并保留集合范围执行关键词搜索。
- **状态：** 已通过。修复了 JSON 请求未指定方法时误用 GET，以及单标签和集合筛选的 SQL 参数绑定顺序。未新增筛选控件。
- **验证：** Playwright 提交真实表单，打开详情，断言保存后的值和标签增删；进入 Civic Communications 集合断言 8 项，搜索 `transit` 后断言 2 项。pytest 覆盖现有集合、单标签及它们与关键词和素材类型并用。

## 2. 组合筛选

- **故事：** 作为内容运营，我能在选定集合里搜索 `harbor`，只看同时带 `approved` 和 `campaign`、不带 `internal` 的素材。
- **验收：** 沿用现有 FTS 字段和分词，空白关键词不限制；可选一个集合或不限制。包含标签须全部命中，排除标签命中任一个即排除。条件与素材类型取交集，仅返回 `active`。标签按完整名称和现有大小写规则匹配；重复不改变结果，包含与排除同名则无结果。页面显示生效条件，支持修改和清除；选项统计不得误标为当前匹配总数。
- **状态：** 已有关键词、集合、素材类型和单标签基础；多标签包含/排除及完整条件展示未实现。验收只要求关键词搜索。
- **验证：** pytest 生成正例、缺包含标签、命中任一排除标签、标签前缀相同、集合外、类型不同及非 `active` 的素材，按 UUID 断言结果；覆盖空白关键词、大小写、重复及冲突。Playwright 在 Library 组合、修改、清除条件并核对结果。

## 3. 稳定排序与分页

- **故事：** 作为内容运营，我能按创建时间升序或降序浏览命中素材，不漏看或重复看见同一条。
- **验收：** 有关键词时也遵守创建时间排序。提供上一页、下一页、匹配总数，页大小固定。数据不变时，同创建时间的素材也不会跨页重复或遗漏。改筛选或排序回到第一页，旧请求晚返回不能覆盖最新结果。空结果、加载失败、非法分页参数及特殊字符输入都有明确行为。
- **状态：** 已有排序控件及后端 `limit`/`offset`；页面未分页，有关键词时仍按相关性排序，未验收稳定顺序及并发更新行为。
- **验证：** pytest 生成超过两页且跨页创建时间相同的素材，拼接各页 UUID 并与两种排序的期望序列比较；验证非法分页值和特殊字符。Playwright 验证翻页边界、总数、重置、空态与失败提示，并延迟旧请求验证最后条件胜出。

## 4. 导出全部匹配素材

- **故事：** 作为内容运营，我能从当前 Library 下载全部命中素材的信息清单。
- **验收：** CSV 应用当前全部筛选（含素材类型）与排序，不受当前页限制。至少含 `uuid`、`title`、`description`、`filename`、`media_type`、`tags`、`created_at`，交付说明注明多标签格式。中文、逗号、引号、换行可无损解析，零结果仍输出表头。复用登录鉴权，支持页面下载和失败提示；不包含素材文件。
- **状态：** 未实现；详情里的单素材文件下载不是 CSV 导出。
- **验证：** pytest 解析 CSV，与静态数据下列表各页拼接的 UUID 和顺序比较；校验字段、特殊字符、零结果和未登录请求。Playwright 在非第一页下载并解析真实文件，再模拟失败验证提示。

## 5. 编辑后查询和导出一致

- **故事：** 作为内容运营，我更新标题、描述或标签后，下一次查询和导出能读到最新数据。
- **验收：** 使用现有详情入口保存元数据、增删标签后，后续查询的内容及匹配资格正确更新，后续 CSV 的行和字段与查询一致。不要求实时订阅或跨请求快照。
- **状态：** 部分通过。已验证标题与描述保存、标签增删、按新标题命中；编辑对组合筛选及 CSV 的影响待验证。
- **验证：** pytest 让素材通过标题、描述或标签编辑分别进入及离开匹配集，每次比较查询和 CSV。Playwright 走详情编辑，再查询并下载断言更新。

## 6. 可复现交付

- **故事：** 作为评审，我能从 Fork 的明确提交复现运行、测试和使用流程。
- **验收：** 保留基线和真实开发历史；交付可访问的 Fork、分支和完整 SHA。提供关键行为的自动化测试和可复现数据，不提交数据库、上传文件、凭据或虚拟环境。`SUBMISSION.md` 须记录运行、验证、实测结果、取舍、限制和未完成项。
- **状态：** 本轮验证原 `seed` 生成 24 个素材和 3 个集合；功能测试数据、CI 和最终提交说明待功能阶段补齐。
- **验证：** 从干净 checkout 安装 `.[dev]`、生成数据、启动应用、运行 pytest 和浏览器流程；核对最终 SHA、CI 与 Draft PR。

## 待确认的 UI 设计

- **筛选布局：** 推荐保留顶部搜索和左栏素材类型，在结果标题下集中放集合、包含/排除标签和生效条件 chips；备选是收进左栏，给网格留更多垂直空间，但组合状态更分散。
- **筛选交互：** 推荐集合单选、标签用自动补全的可移除 chips、改动即时生效并提供清除全部；备选是加「应用筛选」，方便一次改多项，但每次多一步。
- **分页和导出：** 推荐每页 12 项、默认最新优先，网格底部翻页，结果标题旁固定「导出全部匹配（CSV）」；备选每页 24 项，翻页更少但滚动更长。建议隐藏语义搜索入口，避免与关键词验收混淆。
